## Overview

A feature that generates QR codes from content share URLs and downloads them as PNG files. Supports offline-to-online connection scenarios where visitors at fashion shows and exhibitions scan QR codes to instantly access 3D garment content. Beyond simple QR generation library calls, the core was **Canvas API-based custom rendering** and **Share component hierarchy design**.

## Key Implementations

### Canvas API Logo-Composited QR Rendering and Data URL-Based PNG Download

- **Problem**: To download a QR image as a `.png` file in the browser, simply rendering it as an `<img>` tag is insufficient. Extracting an `<img>` tag's image as a file requires separate processing, and with the requirement to composite the CLOSET logo on top of the QR code, DOM-based rendering had limitations. Additionally, the download filename needed to be the content name, but the anchor tag's `download` attribute doesn't work in cross-origin environments.
- **Solve**: Rendered the QR code directly on a `<canvas>` element and composited the logo image using `drawImage()` on the canvas. Extracted the completed canvas as a base64 Data URL via `canvas.toDataURL('image/png')`, then triggered download via programmatic anchor click (`a.href = dataURL`, `a.download = fileName`). Fully handled on the client without cross-origin issues.
- **Result**: Logo-composited QR PNG file download works reliably; response time optimized with a client-complete structure requiring no server requests.

### Share Component Separation by Sharing Method for Reusable QR Structure Design

- **Problem**: The Share feature needed to support multiple sharing methods including URL copy, social media share, and QR code, but without separating each method into independent components, a single Share component would become bloated.
- **Solve**: Designed the QR code generation/rendering component and QR display mini-modal component separately. Organized the structure so sharing method-specific components are managed as independent modules.
- **Result**: Clear responsibility per sharing method component; extensible structure for adding new sharing methods without modifying existing code.

## Retrospective / Lessons Learned

The QR code feature may seem small, but the single requirement of "file download" cascaded into Canvas API → Data URL → Anchor programmatic click as a chain of technical decisions. When working directly with browser APIs, I learned that **"identifying browser constraints first"** determines the implementation direction. I also confirmed that separating components by sharing method from the beginning allows responding to future feature addition requests at almost zero cost.
