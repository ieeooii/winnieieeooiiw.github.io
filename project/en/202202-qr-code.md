## Overview

A feature that generates a QR code from a content sharing URL and downloads it as a PNG file. Supports an offline-to-online scenario where attendees at fashion shows and exhibitions can scan the QR code to immediately access 3D clothing content. Beyond simply calling a QR generation library, the core of this work was **Canvas API-based custom rendering** and **Share component hierarchy design**. The same component was subsequently reused in the Embed Viewer as well, extending the feature without code duplication.

## Key Implementations

### Canvas API-Based QR Code Rendering & PNG Download

- **Problem**: Downloading a QR image as a `.png` file in the browser requires more than simply rendering with an `<img>` tag. Images in `<img>` tags need additional processing for direct file extraction, and there was a requirement to composite the CLOSET logo on top of the QR code — which has limitations with DOM-based rendering. There was also a cross-origin issue where the anchor tag's `download` attribute doesn't function properly.
- **Solve**: Rendered the QR code directly onto a `<canvas>` element, composited the logo image on the canvas with `drawImage()`. Extracted the completed canvas as a base64 Data URL via `canvas.toDataURL('image/png')`, then triggered download via programmatic anchor click (`a.href = dataURL`, `a.download = fileName`). Handled entirely client-side without cross-origin issues.
- **Result**: Logo-composited QR PNG file download works reliably; structure completes entirely client-side without server requests, optimizing response speed.

### Share Component Architecture Design & Embed Viewer Reuse

- **Problem**: The Share feature needed to support multiple sharing methods — URL copy, SNS sharing, QR code, etc. Without separating each method into independent components, a single Share component would become bloated. The Embed Viewer also needed the same QR sharing functionality, but if the component structure is tightly coupled to a specific page, reuse becomes impossible.
- **Solve**: Designed `ShareQRCode.tsx` (QR code generation and rendering) and `ShareQRCodeMiniModal.tsx` (mini modal for displaying QR) as separate components. Organized all Share-related components under a `components/share/right/*` folder structure so that per-sharing-method components are managed as independent modules, improving cohesion. In the Embed Viewer, reused the QR feature simply by importing `ShareQRCode.tsx`.
- **Result**: Share component structure clarified; QR feature integrated into the Embed Viewer without code duplication.

## Retrospective / Lessons Learned

The QR code feature looks small, but a single requirement of "file download" led to a chain of technical decisions: Canvas API → Data URL → Anchor programmatic click. Working directly with browser APIs taught me that **first understanding what browser constraints exist** determines the implementation direction. This work also confirmed that separating components to be reusable from the start means that when a "we need this here too" request comes later, it can be addressed with almost no additional cost.
