# 서비스 다국어 지원 구축 (6개 언어)

| 항목 | 내용 |
|------|------|
| 회사 | CLO Virtual Fashion |
| 서비스 | CLO-SET |
| 기술 스택 | Next.js, TypeScript, i18next |
| 개발 기간 | 2020.02 |
| 인원 | 프론트엔드 1 (담당) |
| 서비스 링크 | style.clo-set.com |

## 소개

글로벌 B2B 플랫폼 CLOSET에 EN·KO·ZH·JA·ES·PT 6개 언어를 지원하는 i18n 시스템을 구축했다. i18next 기반으로 언어별 JSON 파일을 도메인(space, style, account, common 등)별로 분리 관리하며, 컴포넌트에서 `t('key')` 훅으로 참조하는 구조다.

## 주요 구현

### 전체 컴포넌트 다국어 커버리지 확보

- **Problem**: Upload·Multiviewer·Common·LeftMenu·Footer·BannerResendEmail 등 공통 영역에 하드코딩된 영어 텍스트가 다수 존재했다. 다국어 JSON 파일도 도메인별로 일관성 없이 작성되어 있었다.
- **Solve**: 하드코딩 텍스트를 전수 조사하여 언어 JSON에 키를 추가하고 컴포넌트에 적용. 목록 정렬 로직(`sort-by-change-order`)도 언어에 무관하게 동작하도록 정비.
- **Result**: 서비스 전 영역 다국어 커버리지 확보, 이후 신규 기능 PR 시 다국어 적용을 체크하는 팀 컨벤션 형성

### 언어별 레이아웃 버그 수정
- **Problem**: 스페인어(ES)·중국어(ZH)·일본어(JA)에서 텍스트 길이가 영어 대비 최대 1.5~2배 길거나 짧아, 고정 너비 컨테이너에서 텍스트가 잘리거나 레이아웃이 깨지는 현상이 발생했다. 특히 버튼 라벨이 길어서 버튼이 밀려나거나 줄바꿈되는 케이스가 빈번했다.
- **Solve**: 텍스트가 길어질 수 있는 UI 요소에 `overflow: hidden + text-overflow: ellipsis` 또는 유연한 `flex` 레이아웃으로 전환. 언어별 JSON도 UX를 고려한 적절한 길이로 번역 수정.
- **Result**: 전 언어에서 동일한 수준의 UI 품질 유지
- **Insight**: "영어 기준으로만 UI를 짜면 반드시 깨진다." 이후 모든 UI 작업에서 다국어 텍스트 길이 변화를 사전에 고려하는 습관이 생겼다.
