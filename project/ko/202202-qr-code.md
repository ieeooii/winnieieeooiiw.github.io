## 소개

콘텐츠 공유 URL을 QR 코드로 생성하고 PNG 파일로 다운로드하는 기능이다. 패션쇼·전시 현장에서 관람객이 QR 코드를 스캔해 3D 의류 콘텐츠로 즉시 접근할 수 있는 오프라인-온라인 연결 시나리오를 지원한다. 단순한 QR 생성 라이브러리 호출을 넘어, **Canvas API 기반 커스텀 렌더링**과 **Share 컴포넌트 계층 설계**가 핵심이었다.

## 주요 구현

### Canvas API로 로고 합성 QR 렌더링과 Data URL 기반 PNG 다운로드

- **Problem**: 브라우저에서 QR 이미지를 `.png` 파일로 다운로드하려면 단순히 `<img>` 태그로 렌더링하는 것만으로는 부족하다. `<img>` 태그의 이미지는 직접 파일로 추출하기 위한 별도 처리가 필요하며, 특히 QR 코드 위에 CLOSET 로고를 합성하는 요구사항이 있어 DOM 기반 렌더링으로는 한계가 있었다. 또한 다운로드 파일명을 콘텐츠 이름으로 지정해야 하는데, anchor 태그의 `download` 속성이 cross-origin 환경에서 동작하지 않는 문제도 있었다.
- **Solve**: QR 코드를 `<canvas>` 엘리먼트에 직접 렌더링하고, 로고 이미지를 `drawImage()`로 캔버스 위에 합성. 완성된 캔버스를 `canvas.toDataURL('image/png')`로 base64 Data URL로 추출한 뒤, programmatic anchor click(`a.href = dataURL`, `a.download = fileName`)으로 다운로드 트리거. cross-origin 문제 없이 클라이언트에서 완전히 처리.
- **Result**: 로고 합성 QR PNG 파일 다운로드 안정적으로 동작, 서버 요청 없이 클라이언트에서 완결되는 구조로 응답속도 최적화

### 공유 방식별 컴포넌트 분리로 QR 기능 재사용 가능한 구조 설계

- **Problem**: Share 기능은 URL 복사, SNS 공유, QR 코드 등 여러 공유 방식을 지원해야 했는데, 각 방식을 독립된 컴포넌트로 분리하지 않으면 단일 Share 컴포넌트가 비대해지는 문제가 발생한다.
- **Solve**: QR 코드 생성·렌더링 컴포넌트와 QR 표시용 미니 모달 컴포넌트를 분리 설계. 공유 방식별 컴포넌트가 독립 모듈로 관리되도록 구조 정리.
- **Result**: 공유 방식별 컴포넌트 책임 명확화, 이후 공유 방식 추가 시 기존 코드 수정 없이 확장 가능한 구조

## 회고 / 아쉬웠던 점

QR 코드 기능은 작아 보이지만, "파일 다운로드"라는 요구사항 하나가 Canvas API → Data URL → Anchor programmatic click이라는 연쇄적인 기술 선택으로 이어졌다. 브라우저 API를 직접 다루는 작업에서는 **"어떤 브라우저 제약이 있는가"를 먼저 파악하는 것**이 구현 방향을 결정한다는 것을 배웠다. 또한 컴포넌트를 처음부터 공유 방식별로 분리해 두면, 이후 기능 추가 요청에 거의 비용 없이 대응할 수 있다는 것을 이 작업에서 확인했다.
