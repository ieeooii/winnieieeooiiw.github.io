## 소개

패션 브랜드 관리자가 의류 카테고리를 최대 4단계 깊이의 계층 구조로 관리하는 설정 페이지다. 루트 카테고리부터 하위 카테고리까지 클릭 탐색으로 열어가며 추가·수정·삭제하고, 각 계층 내에서 드래그 앤 드롭으로 순서를 재배치할 수 있다. **컬럼(열) 기반 트리 탐색 UI**를 설계했는데, 사용자가 어떤 카테고리를 선택했느냐에 따라 보이는 열의 수와 내용이 동적으로 결정된다. MobX `Map` 기반의 플랫 자료구조와 컬럼 컴퓨팅 로직이 이 기능의 핵심 설계 과제였다.

## 주요 구현

### 선택 경로 배열 기반 컬럼 트리 탐색 UI 설계

- **Problem**: 4단계 깊이의 카테고리 트리를 UI로 표현할 때, 전통적인 들여쓰기 방식은 깊이가 깊어질수록 가로 공간을 많이 차지하고 현재 선택 경로가 한눈에 보이지 않는다. macOS Finder의 컬럼 뷰처럼 선택된 노드의 자식들이 오른쪽 새 열에 펼쳐지는 구조가 필요했다.
- **Solve**: 각 깊이에서 선택된 인덱스를 담은 "선택 경로 배열"을 MobX observable로 관리. 이 배열을 순회하며 표시할 컬럼 목록을 계산하는 로직을 `useEffect`에서 수행 — 선택된 노드의 ID를 기준으로 플랫 맵에서 자식 노드들을 필터링해 다음 컬럼 데이터를 생성. 렌더링은 계산된 컬럼 목록을 매핑해 열 단위 컴포넌트로 표시.
- **Result**: 선택 경로가 항상 시각적으로 강조된 컬럼 트리 UI 구현, 4단계 깊이에서도 현재 위치가 명확하게 표시됨

### 플랫 Map 구조로 트리 성능 확보

- **Problem**: 4단계 계층 구조를 중첩 트리 객체로 관리하면 특정 노드를 찾거나 업데이트할 때 재귀 탐색이 필요하여 성능과 코드 복잡도가 높아진다. 또한 카테고리 총 수 제한 초과 여부를 빠르게 판단해야 했다.
- **Solve**: 모든 카테고리를 `Map<id, node>` 형태로 플랫하게 저장. 특정 노드 조회는 `Map.get(id)`로 O(1) 처리. 컬럼별 표시 데이터는 부모 ID를 기준으로 맵을 필터링해 동적 계산. 총 수 초과 여부는 `map.size`로 즉시 판단하여 임계치 초과 시 안내 메시지 표시.
- **Result**: 단계가 늘어나도 조회·업데이트 성능 일정, 총 수 제한 초과 시 즉각적인 UI 피드백

### 드래그 앤 드롭 인터랙션과 UI·서버 상태 일관성 유지

- **Problem**: 각 컬럼 내에서 카테고리 순서를 드래그 앤 드롭으로 변경해야 했다. `react-beautiful-dnd`는 당시 React Strict Mode 호환성 이슈가 있었고, 드래그 완료 시 선택 상태(selected index)도 새 위치에 맞게 동기화해야 하는 요구사항이 있었다.
- **Solve**: `react-sortablejs`로 각 컬럼을 드래그 가능한 리스트로 구성. 드래그 완료 이벤트에서 스토어 액션으로 서버에 새 순서를 저장하는 동시에, 선택 인덱스도 새 위치로 업데이트. 드래그 애니메이션 CSS 클래스를 전역 상수로 정의하여 모든 컬럼에서 일관된 드래그 UX 제공.
- **Result**: 컬럼 내 드래그 앤 드롭 정상 동작, 드래그 완료 후 선택 상태와 서버 데이터 동기화

### 파괴적 액션의 조건부 노출과 이중 확인 플로우 설계

- **Problem**: 카테고리 on/off, 전체 초기화, 타 회사 구조 복사는 각각 접근 조건과 위험도가 다른 운영성 액션이다. 단순 버튼으로 나열하면 실수로 실행될 위험이 있고, 비활성화 상태에서 편집 UI가 그대로 노출되면 사용자에게 혼란을 준다.
- **Solve**: 카테고리 기능이 비활성화된 상태에서는 트리 편집 UI 대신 활성화 안내 화면을 표시하고, 활성화 시에만 편집 UI를 노출. 초기화와 타 회사 구조 복사는 별도 옵션 모달로 분리해 의도적인 진입을 유도. 카테고리 삭제 시에는 하위 카테고리까지 연쇄 삭제된다는 경고를 확인 모달에 포함.
- **Result**: 기능별 접근 조건과 위험도를 UI로 명확히 분리, 파괴적 액션에 대한 이중 확인 플로우 구현

## 회고 / 아쉬웠던 점

컬럼 트리의 핵심은 "현재 열려 있는 경로"를 얼마나 간결하게 표현하느냐였다. 각 깊이에서 선택된 인덱스를 담은 배열 하나가 전체 트리의 열림 상태를 나타내고, 이 배열을 순회하는 로직이 표시할 컬럼 목록을 만들어낸다. 처음에는 각 깊이별로 별도 state를 관리하려 했는데, 결국 "경로 배열 → 컬럼 목록"의 단방향 파생 구조가 훨씬 단순하고 예측 가능하다는 것을 깨달았다. **UI 상태를 최소한의 정보로 표현하고 나머지는 파생(derive)하는 방식이 복잡한 트리 UI에서도 유효하다**는 것을 배운 작업이었다.
