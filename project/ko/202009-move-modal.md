## 소개

3D 의류 콘텐츠 파일을 다른 스토리지(parent storage / child storage)로 이동하는 Move 기능의 UI 전체를 개발했다. 단일 파일 이동부터 다중 선택(MultiSelect) 일괄 이동, 스토리지 단위 이동까지 지원하는 복합 플로우다. **"공간 선택 → 이동 확인 → 완료"** 3단계 모달 체인을 설계했으며, 공간 계층 구조를 지연 로딩(Lazy Load) 트리로 탐색하면서 권한·깊이 제한을 실시간으로 검증하는 것이 핵심 기술 과제였다. 이후 Copy 기능도 동일한 공간 선택 트리 컴포넌트를 재사용하도록 설계하여 두 기능의 UI 일관성을 확보했다.

## 주요 구현

### 모달 체인 오케스트레이션 — 단계별 독립 컴포넌트와 단일 컨트롤러 구조

- **Problem**: 아이템 이동은 단순한 "확인 버튼 클릭"이 아니라 ① 대상 공간 탐색·선택, ② 이동 결과 확인(되돌릴 수 없는 액션), ③ 완료 후 이동된 위치로 바로 이동하는 세 단계가 필요했다. 이 세 단계를 하나의 모달 컴포넌트에 모두 넣으면 상태와 UI가 뒤엉키고, 각각을 독립 모달로 분리하면 단계 간 데이터 전달과 열림/닫힘 상태 제어가 복잡해진다.
- **Solve**: 각 단계를 독립된 모달 컴포넌트로 분리하되, 상위 컨트롤러 컴포넌트가 전체 상태 흐름을 오케스트레이션. 선택된 대상 공간 데이터는 React `useState`로 단계 간 전달. 각 단계의 열림/닫힘 상태는 독립적인 boolean state로 관리하여 특정 단계만 닫거나 전체를 한 번에 닫는 공통 핸들러를 별도로 설계.
- **Result**: 각 단계 컴포넌트가 자신의 역할에만 집중하는 단일 책임 구조, 완료/취소/오류 등 모든 종료 경로에서 모달 상태가 일관되게 정리됨

### 클릭 시점 페치와 메모이제이션으로 지연 로딩 트리 탐색 구현

- **Problem**: 스토리지 구조는 parent storage → child storage → file처럼 다단계 계층을 가진다. 이동 대상을 선택하는 트리 UI에서 전체 계층을 한 번에 불러오면 API 응답이 느리고 불필요한 데이터까지 로드된다. 또한 사용자가 이동하면 안 되는 공간(권한 없음, 최대 중첩 깊이 초과)을 트리에서 미리 차단해야 했다.
- **Solve**: 트리 노드를 클릭해서 펼칠 때만 자식 노드를 API로 페치하는 지연 로딩(Lazy Load) 패턴 구현. 이미 불러온 노드는 메모이제이션 캐시에 저장하여 동일 노드 재펼침 시 API 재호출 없이 즉시 표시. 공간 최대 중첩 깊이 제한을 트리 렌더링 단계에서 적용하여 허용 깊이를 초과하는 노드는 선택 불가 처리. 업로드 권한이 없는 공간은 트리 페치 시 서버 레벨에서 필터링하여 노출 자체를 차단.
- **Result**: 대용량 계층 구조에서도 빠른 초기 로드, 사용자가 선택할 수 없는 공간을 트리 탐색 단계에서 미리 차단하여 이동 실패 케이스 원천 감소

### 매핑 테이블 기반 이동 타입 분기로 확장 가능한 구조 설계

- **Problem**: 이동 대상이 무엇이냐(file / parent storage / child storage)에 따라 호출해야 하는 API와 이동 가능한 목적지 타입이 달랐다. file은 child storage로만, child storage는 parent storage로만 이동 가능한 제약이 있었고, 다중 선택 일괄 이동은 또 다른 API를 사용해야 했다. 이 분기를 컴포넌트 내부에 모두 하드코딩하면 새로운 공간 타입이 추가될 때마다 수정 범위가 커진다.
- **Solve**: 공간 타입과 이동 가능한 목적지 타입을 매핑 테이블(객체 리터럴)로 정의하여 분기 로직을 선언적으로 관리. 단일 이동 / 룸 이동 / 다중 이동 각각에 대해 별도의 뮤테이션 함수를 분리하여 컨트롤러가 타입에 따라 적절한 함수를 선택하는 방식으로 구현.
- **Result**: 새로운 공간 타입이 추가되더라도 매핑 테이블만 수정하면 되는 확장 가능한 구조

### 콜백 prop으로 이동 완료 후 사이드 이펙트를 부모에 명시적 위임

- **Problem**: 이동 완료 후 처리해야 할 사이드 이펙트가 세 가지 있었다. ① 출발지 목록에서 이동된 아이템이 사라지도록 목록 갱신, ② 다중 선택 상태에서 이동한 경우 선택 항목 초기화, ③ 완료 모달에서 "이동된 위치로 이동" 클릭 시 올바른 공간 경로로 라우팅. 초기 구현에서는 이동 완료 후 목록이 갱신되지 않아 이미 이동된 아이템이 원래 위치에 남아 있는 것처럼 보이는 버그가 있었다.
- **Solve**: 목록 갱신·선택 초기화 콜백 prop을 통해 완료 모달 닫힘 시점에 부모 컴포넌트의 함수를 호출하는 구조 설계. 완료 모달의 "이동된 위치로 이동" 버튼은 이동 타입에 따라 올바른 경로를 생성하는 유틸 함수로 동적 라우팅 처리.
- **Result**: 이동 완료 후 세 가지 사이드 이펙트가 누락 없이 순서대로 처리, 사용자가 이동 결과를 즉시 확인 가능

### Move·Copy 공통 트리 컴포넌트 재사용 및 dynamic import SSR 비활성화

- **Problem**: 이동(Move)과 복사(Copy) 두 기능 모두 "공간 트리에서 대상을 선택한다"는 공통 UX를 가진다. 각 기능마다 별도로 트리 UI를 구현하면 코드가 중복되고, 이후 트리 동작을 수정할 때 두 곳을 동시에 변경해야 한다. 또한 트리 컴포넌트는 스크롤바 위치 계산 등 브라우저 DOM에 의존하는 로직이 포함되어 있어 SSR 환경에서 실행되면 안 됐다.
- **Solve**: 공간 선택 트리 컴포넌트를 처음부터 독립 모듈로 설계하여 Move·Copy 양쪽에서 동일하게 재사용. `next/dynamic`으로 동적 임포트하여 SSR을 비활성화해 DOM 의존 로직의 서버 실행을 차단. 최근 이동한 공간 목록("Recent" 탭)을 비동기로 로드하여 자주 이동하는 위치에 빠르게 접근할 수 있는 UX 제공.
- **Result**: 트리 UI 로직 단일 관리, DOM 의존 코드의 SSR 실행 오류 방지

## 회고 / 아쉬웠던 점

이 기능에서 가장 복잡한 부분은 "모달 체인의 상태 관리"였다. 각 단계가 독립적이어야 하지만, 전체 흐름은 하나의 컨트롤러가 조율해야 한다. 처음에는 각 단계의 상태를 부모 컴포넌트에 모두 올려서 관리했는데, 단계가 늘어날수록 props가 많아지고 어떤 단계에서 무슨 상태를 쓰는지 추적하기 어려워졌다. 결국 각 단계 컴포넌트가 자신의 열림/닫힘 상태는 스스로 소유하고, 단계 간 전달이 필요한 데이터(선택된 공간 정보)만 상위로 올리는 방식으로 정리하면서 구조가 단순해졌다. 또한 이동 완료 후 "목록 갱신"이 누락된 버그를 수정하면서, **모달처럼 부모로부터 분리된 컴포넌트에서 발생하는 사이드 이펙트는 콜백 prop으로 명시적으로 끌어올려야** 한다는 것을 다시 확인했다.
