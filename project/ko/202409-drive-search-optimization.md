CLOSET의 콘텐츠 검색 페이지와 Room(파일·작업물을 보관·공유하는 워크스페이스 단위) 목록 페이지에서 Virtuoso 가상 스크롤 라이브러리와 React Query Infinite Scroll 조합에서 발생한 두 가지 버그를 수정했다. Virtuoso는 IntersectionObserver 대신 실제 DOM 렌더링 영역(`visibleRange`)을 기반으로 현재 보이는 항목만 렌더링하여 대량 리스트 성능을 확보하는 라이브러리다.

## 주요 구현

### 무한 리렌더링 버그 — Windows HiDPI 디스플레이

- **Problem**: Windows HiDPI 환경에서 Room 목록 페이지를 열면 다음 페이지 요청 함수가 멈추지 않고 반복 호출되며 무한 API 요청과 리렌더링이 발생했다. Mac + 일반 해상도에서는 전혀 재현되지 않았기 때문에 원인 파악이 어려웠다. HiDPI 환경을 가진 팀원의 Windows 머신에서만 재현 가능해 디버깅 환경 자체를 구축하는 것이 첫 번째 과제였다.
- **Solve**: DOM 높이 측정 방식이 HiDPI 환경의 브라우저 리페인트 사이클과 어긋나 "컨텐츠가 컨테이너를 채우지 못했다"는 판단이 반복되는 것이 원인이었다. 기존에는 특정 CSS 클래스 엘리먼트의 `clientHeight`를 직접 참조했는데, `requestAnimationFrame`으로 DOM 측정 타이밍을 브라우저 리페인트 이후로 맞추고, 스크롤 컨테이너의 `scrollHeight`를 기준으로 변경하여 해결. `isFetching` 가드를 추가해 요청 중 중복 호출도 차단.
- **Result**: Windows HiDPI 환경에서 무한 루프 완전 해소

### 복사 낙관적 업데이트 — 순서 보장과 카운트 동기화

- **Problem**: Context Menu에서 콘텐츠 복사를 실행하면 두 가지 문제가 발생했다. 첫째, 복사 완료 후 목록에 원본과 복사본이 중복 표시되거나 카운트가 실제 서버 데이터와 맞지 않았다. 둘째, 복사 직후 스켈레톤 로더가 무한 표시됐다. 원인은 낙관적 업데이트로 목록 앞에 복사본을 추가할 때 총 카운트를 함께 증가시키지 않아 "아직 로드할 항목이 남아있다"고 판단하고, 캐시 무효화와 임시 아이템 제거가 순서 보장 없이 실행되어 상태 불일치가 발생한 것이었다.
- **Solve**: 낙관적 업데이트에서 목록 앞에 복사본을 추가할 때 총 카운트를 즉시 함께 증가시켜 스켈레톤 로더가 사라지도록 처리. 복사 성공 콜백에서 임시 아이템 롤백을 먼저 수행한 뒤 목록 캐시를 무효화하여 서버에서 최신 상태를 재조회하도록 순서를 명시적으로 보장.
- **Result**: 복사 후 목록 중복 표시 해소, 스켈레톤 무한 표시 해소, 카운트 정합성 확보

### 페이지네이션 경쟁 상태 방지

- **Problem**: 가상 스크롤 환경에서 페이지 로드 함수가 빠르게 연속 호출될 경우 동일 페이지를 중복 요청하거나, API 오류 발생 시 페이지 번호가 잘못 증가하는 문제가 있었다. 또한 필터 변경 시 이전 페이지 요청이 완료되기 전에 새 요청이 시작되면 취소되지 않은 이전 응답이 목록에 섞일 수 있었다.
- **Solve**: 현재 요청 중인 페이지 번호를 확정 페이지 번호와 분리하여 추적. `isFetching` 상태를 가드로 두어 요청 중 중복 호출 차단. API 오류 발생 시 요청 중 페이지 번호를 롤백하여 다음 시도 시 동일 페이지를 재요청하도록 처리. 필터 변경 시 AbortController로 이전 페이지 요청을 취소하여 응답 혼입 방지. 목록 병합 시 ID 기반 중복 제거를 적용하여 컬러웨이 뷰 등 동일 아이템이 복수 렌더링되는 환경에서의 중복 방지.
- **Result**: 빠른 스크롤·필터 전환 시에도 중복 요청 없이 페이지 순서 보장, API 오류 후 재시도 정상 동작

## 회고 / 아쉬웠던 점

"Mac에서는 안 나오는 버그"는 항상 디버깅이 어렵다. Virtuoso 버그는 HiDPI 환경 없이는 재현조차 불가능했기 때문에, 먼저 재현 환경을 확보하는 것이 디버깅의 전제임을 다시 한 번 체감했다. 픽셀 단위 계산이 들어가는 UI 로직은 OS/해상도/브라우저 조합에 따라 미묘하게 달라질 수 있으며, 가정에 의존하는 정수 비교보다는 명시적인 `Math.floor/ceil`이나 fetch 상태 가드로 방어해야 한다는 것을 배웠다.
