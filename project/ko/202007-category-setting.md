# 브랜드 카테고리 설정 — 다단계 계층 구조 관리

| 항목 | 내용 |
|------|------|
| 회사 | CLO Virtual Fashion |
| 카테고리 | SaaS |
| 서비스 | CLO-SET |
| 기술 스택 | Next.js, TypeScript, MobX, react-sortablejs, Emotion |
| 개발 기간 | 2020.07 ~ 2020.12 |
| 서비스 링크 | style.clo-set.com |

## 소개

패션 브랜드 관리자가 의류 카테고리를 최대 4단계 깊이의 계층 구조로 관리하는 설정 페이지다. 루트 카테고리부터 하위 카테고리까지 클릭 탐색으로 열어가며 추가·수정·삭제하고, 각 계층 내에서 드래그 앤 드롭으로 순서를 재배치할 수 있다. **컬럼(열) 기반 트리 탐색 UI**를 설계했는데, 사용자가 어떤 카테고리를 선택했느냐에 따라 보이는 열의 수와 내용이 동적으로 결정된다. MobX `Map` 기반의 플랫 자료구조와 컬럼 컴퓨팅 로직이 이 기능의 핵심 설계 과제였다.

## 주요 구현

### 컬럼 기반 트리 탐색 UI 설계

- **Problem**: 4단계 깊이의 카테고리 트리를 UI로 표현할 때, 전통적인 들여쓰기 방식은 깊이가 깊어질수록 가로 공간을 많이 차지하고 현재 선택 경로가 한눈에 보이지 않는다. CLOSET은 Finder(macOS)의 컬럼 뷰와 유사한 방식으로, 선택된 노드의 자식들이 오른쪽 새 열에 펼쳐지는 구조가 필요했다.
- **Solve**: `openedCategoryIdxes` 배열로 현재 선택된 경로(각 깊이에서 선택된 인덱스)를 MobX observable로 관리. `useEffect`에서 이 배열을 `reduce`로 순회하며 표시할 컬럼 목록(`groupList`)을 계산 — 선택된 노드의 `CategoryId`를 기준으로 `categoryMap`에서 자식 노드들을 필터링하여 다음 컬럼 데이터를 생성. 렌더링은 `groupList` 배열을 매핑하여 열 단위 컴포넌트(`CategoryTreeColumn`)로 표시.
- **Result**: 선택 경로가 항상 시각적으로 강조된 컬럼 트리 UI 구현, 4단계 깊이에서도 현재 위치가 명확하게 표시됨

### MobX Map 기반 플랫 자료구조 + 필터링

- **Problem**: 4단계 계층 구조를 중첩 트리 객체로 관리하면 특정 노드를 찾거나 업데이트할 때 재귀 탐색이 필요하여 성능과 코드 복잡도가 높아진다. 또한 카테고리 총 수 제한(최대 수백 개)을 초과 여부를 빠르게 판단해야 했다.
- **Solve**: 모든 카테고리를 `Map<CategoryId, Category>`로 플랫하게 저장. 특정 노드 조회는 `Map.get(id)`로 O(1) 처리. 컬럼별 표시 데이터는 `filterCategoryMap(categoryMap, ({ ParentId }) => ParentId === targetId)`로 동적 계산. 총 수 초과 여부는 `categoryMap.size`로 즉시 판단하여 임계치 초과 시 `CategoryTotalFullError` 메시지 표시.
- **Result**: 단계가 늘어나도 조회·업데이트 성능 일정, 총 수 제한 초과 시 즉각적인 UI 피드백

### 드래그 앤 드롭 순서 변경 (react-sortablejs)

- **Problem**: 각 컬럼 내에서 카테고리 순서를 드래그 앤 드롭으로 변경해야 했다. `react-beautiful-dnd`는 당시 React Strict Mode 호환성 이슈가 있었고, 드래그 완료 시 선택 상태(selected index)도 새 위치에 맞게 동기화해야 하는 요구사항이 있었다.
- **Solve**: `react-sortablejs`(`ReactSortable`)로 각 컬럼을 드래그 가능한 리스트로 구성. 드래그 완료 이벤트에서 `changeCategoryOrder({ categories })` 스토어 액션으로 서버에 새 순서 저장. `selectCategory(newIndex, depth)`를 함께 호출하여 드래그 후 선택 인덱스를 새 위치로 업데이트. 드래그 애니메이션 CSS 클래스를 전역 상수로 정의하여 모든 컬럼에서 일관된 드래그 UX 제공.
- **Result**: 컬럼 내 드래그 앤 드롭 정상 동작, 드래그 완료 후 선택 상태와 서버 데이터 동기화

### 카테고리 활성화 / 초기화 / 타 회사 복사

- 카테고리 기능 자체를 활성화/비활성화하는 토글 설계 — 비활성화 상태에서는 `ActivateCategory` 화면을 표시하고, 활성화 상태에서만 트리 편집 UI 노출
- 전체 카테고리 초기화(`CategoryResetOption`) 및 타 회사 카테고리 구조를 복사해오는(`CategoryResetOption`) 기능 개발 — 패션 브랜드가 초기 세팅 시 기존 구조를 재활용할 수 있도록 지원
- 카테고리 삭제 시 하위 카테고리까지 연쇄 삭제된다는 경고 문구(`Trans` 컴포넌트로 다국어 강조 처리)를 포함한 확인 모달 구현

## 회고 / 아쉬웠던 점

컬럼 트리의 핵심은 "현재 열려 있는 경로"를 얼마나 간결하게 표현하느냐였다. `openedCategoryIdxes` 배열 하나가 전체 트리의 열림 상태를 나타내고, 이 배열을 `reduce`로 순회하는 로직이 표시할 컬럼 목록을 만들어낸다. 처음에는 각 깊이별로 별도 state를 관리하려 했는데, 결국 이 "경로 배열 → 컬럼 계산"의 단방향 변환 구조가 훨씬 단순하고 예측 가능하다는 것을 깨달았다. **UI 상태를 "현재 선택 경로"라는 최소한의 정보로 표현하고, 나머지는 파생(derive)하는 방식이 복잡한 트리 UI에서도 유효하다**는 것을 배운 작업이었다.
