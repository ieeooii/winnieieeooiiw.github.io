## 소개

협업 기능으로 두 종류의 코멘트 시스템을 동시에 개발했다. Annotation은 3D 뷰어 캔버스 위에 핀을 꽂아 특정 위치에 코멘트를 다는 시스템이고, Comment는 콘텐츠 페이지에 일반 스레드 형태로 달리는 시스템이다. 두 시스템 모두 텍스트 + 이미지 첨부·멘션(@mention)·대댓글(reply)을 지원하며, 에디터와 멘션 컴포넌트는 공통화하고 각 시스템이 조합하는 방식으로 설계했다.

## 주요 구현

### 어노테이션 핀 좌표 정규화 — 3단계 좌표 변환

- **Problem**: 3D 뷰어는 컨테이너 크기와 이미지 스케일에 따라 렌더링 영역이 동적으로 변한다. 마우스 클릭 좌표를 그대로 저장하면 뷰포트 크기가 달라질 때 핀 위치가 어긋나고, 다른 사용자 화면에서도 동일한 위치를 가리키지 못한다.
- **Solve**: 좌표를 세 단계로 변환하는 구조를 설계했다. ① 마우스 이벤트의 client 좌표에서 뷰어 컨테이너의 offset을 빼 캔버스 기준 좌표로 변환. ② 뷰포트 스케일 오프셋을 MobX observable로 추적하여, 뷰포트 크기 변화에 반응적으로 대응. ③ 캔버스 좌표를 스케일로 나눠 Model Space의 정규화 좌표로 변환한 뒤 서버에 저장. 렌더링 시에는 역변환으로 현재 뷰포트에 맞는 화면 좌표를 계산한다. 좌표 변환 함수를 컴포넌트 트리 전체에 props로 전달하는 구조로 변환 로직을 단일 지점에서 관리했다.
- **Result**: 뷰포트 크기·스케일이 달라져도 핀이 항상 동일한 3D 의상 위치를 가리킴. 사용자 간 핀 위치 불일치 없음.

### 어노테이션 버전 간 복사 — MobX 중첩 Observable

- **Problem**: 이전 버전에 달린 어노테이션을 특정 버전으로 복사하는 기능이 필요했다. 복사 모달에서 버전별 어노테이션 목록의 체크박스 상태를 반응적으로 관리해야 했는데, MobX는 기본적으로 배열 내부 객체의 중첩 필드 변화를 관찰하지 않아 체크박스 상태 변경이 UI에 반영되지 않는 문제가 있었다.
- **Solve**: 각 버전 항목 내 어노테이션 배열을 `observable()`로 명시적으로 래핑하여 중첩 observable 배열로 구성했다. `@computed`로 선택된 항목만 필터링한 파생 상태를 선언해, 선택 변경 시 자동으로 파생 상태가 갱신되도록 했다. 선택된 항목에는 순서 번호를 부여하고, 선택/해제 시마다 전체 선택 목록을 재번호화하여 표시 순서의 일관성을 유지했다. Enzyme으로 행위 주도 테스트 코드를 작성해 복사 플로우를 검증했다. 복사 완료 후 새로 생성된 핀들을 flash 하이라이트로 시각적으로 표시했다.
- **Result**: 체크박스 상태와 선택 순서가 실시간으로 동기화됨. 복사 완료 시 대상 핀 위치를 즉시 시각적으로 확인 가능.

### 핀 드래그와 undo/redo 통합

- **Problem**: 사용자가 핀을 드래그해 위치를 바꾼 뒤 실수를 되돌리려 할 때, 드래그 전·후 좌표를 이력으로 관리해야 했다. 핀 생성과 드래그 이동이 동일한 undo/redo 스택에서 함께 관리되어야 했다.
- **Solve**: undo/redo 히스토리를 함수형 콜백 쌍(`undo: () => void`, `redo: () => void`)으로 추상화하여 히스토리 스택에 저장하는 구조로 설계했다. 드래그 종료 시점에 이동 전 좌표와 이동 후 좌표를 클로저에 캡처하여 undo 시 이전 위치로, redo 시 이후 위치로 복원하도록 구현했다. 핀 생성도 동일한 인터페이스로 통합했다.
- **Result**: 핀 생성과 드래그 이동이 단일 히스토리 스택에서 일관되게 undo/redo 가능.

### 이미지 Drag & Drop과 키보드 단축키

- **Problem**: 이미지를 에디터 영역에 드래그해서 바로 첨부하는 UX가 요구됐다. `Cmd+Enter`(Mac) / `Ctrl+Enter`(Windows) 단축키로 댓글을 제출하는 기능도 필요했다. 에디터 내부에서 Enter가 줄바꿈과 제출 두 가지 역할을 해야 했기 때문에 modifier key 조합을 정확히 구분해야 했다.
- **Solve**: 드래그 앤 드롭 처리를 별도 컴포넌트로 분리하여 `dragover` / `drop` 이벤트를 처리하고, 드롭된 파일의 MIME type을 확인하여 `image/*` 외 파일은 드롭을 차단했다. OS 판별(`navigator.userAgent`)로 Mac은 `metaKey`, Windows/Linux는 `ctrlKey`를 감지하는 키보드 핸들러를 구현하여 Enter와 제출을 정확히 분리했다. 클립보드 붙여넣기도 동일한 파일 처리 파이프라인으로 연결했다.
- **Result**: 이미지 드래그 앤 드롭 첨부 가능, 플랫폼별 키보드 단축키 제출 지원

### 멘션(@mention) 드롭다운 위치 계산 버그 수정

- **Problem**: 멘션 목록이 화면 하단에 위치한 에디터에서 활성화될 때, 드롭다운이 viewport 아래쪽으로 벗어나 잘리는 align 버그가 발생했다. 라이브러리가 드롭다운의 표시 방향을 에디터 위치에 관계없이 항상 아래쪽으로 고정했기 때문이었다. 또한 이미 멘션된 멤버가 드롭다운 후보 목록에 다시 표시되는 문제도 있었다.
- **Solve**: 에디터 컴포넌트의 `getBoundingClientRect()`로 현재 위치를 계산하고, viewport 하단까지 남은 공간과 드롭다운 높이를 비교하여 공간이 부족하면 드롭다운을 위쪽으로 표시하도록 동적 전환 로직을 추가했다. 멘션 후보 목록은 Quill 에디터의 현재 Delta 콘텐츠를 분석해 이미 멘션된 멤버를 필터링하여 중복 멘션을 방지했다.
- **Result**: 화면 어느 위치에서도 멘션 드롭다운이 잘리지 않고 정상 표시. 이미 멘션한 멤버는 후보 목록에서 제외.

### 2단계 댓글 계층 이벤트 처리

- **Problem**: Annotation Comment는 Thread와 Reply의 2단계 계층 구조를 가지며, 각 레벨에서 ESC(취소) / Enter(제출) 키보드 이벤트가 독립적으로 동작해야 했다. 대댓글 입력 중 ESC를 눌렀을 때 대댓글 입력창만 닫히고 상위 Thread에는 영향을 주지 않아야 했는데, 이벤트가 부모 컴포넌트까지 버블링되어 상위 Thread도 함께 닫히는 문제가 있었다.
- **Solve**: Thread 레벨과 Reply 레벨로 계층을 분리하고, Reply 레벨의 키보드 핸들러에서 `event.stopPropagation()`을 호출하여 Thread 레벨까지 버블링을 차단했다. 각 레벨의 open/close 상태를 독립적인 로컬 state로 관리했다. 핀과 툴팁 사이 gap에서 포인터가 잠깐 벗어날 때 발생하는 hover flickering은, 이전에 hover 중이던 객체의 leave를 다음 진입 시점까지 지연 처리하는 방식으로 해결했다.
- **Result**: 2단계 댓글 계층에서 독립적인 키보드 인터랙션 동작. ESC 이벤트가 계층 간 의도치 않게 전파되지 않음. hover flickering 없음.

## 회고 / 아쉬웠던 점

에디터 컴포넌트는 UX 요구사항이 많고 엣지 케이스가 풍부한 영역이다. 특히 이 작업에서 "이벤트 위임과 `stopPropagation`은 서로 반대 방향으로 작용한다"는 것을 명확히 이해하게 됐다. 이벤트 위임은 버블링을 이용하는 것이고 `stopPropagation`은 그것을 끊는 것이기 때문에, 두 패턴을 함께 쓸 때는 어느 레벨에서 끊어야 하는지를 컴포넌트 계층 설계 단계에서 미리 정해야 한다.
