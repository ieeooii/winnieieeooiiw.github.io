## 소개

![글로벌 배너/모달 중 사용량 초과 알림 배너](/images/projects/202105-global-banner.png)

이메일 미인증·사용량 한도 임박·공지 등 여러 배너가 동시에 표시 조건을 만족할 수 있는 상황을 처리하기 위해, 우선순위 기반 배너 큐 시스템을 설계·구현했다. 배너를 하나씩 순차 표시하고 닫으면 다음 배너로 자동 진행하며, 각 배너의 표시 여부는 API 데이터에 의존한다.

## 주요 구현

### 우선순위 배열 큐 + async 조건 검사로 다중 배너 순차 표시 설계

- **Problem**: 이메일 미인증·사용량 한도 임박 등 여러 배너가 동시에 조건을 만족할 수 있다. 각 배너의 표시 조건이 API 비동기 데이터에 의존해 마운트 시점에 동기적으로 우선순위를 계산할 수 없었다. 또한 Enterprise 전용 배너를 별도 배열로 분리해 관리하면, 새 배너 타입 추가 시 여러 곳을 동시에 수정해야 했다.
- **Solve**: 배너 타입을 우선순위 순서로 정렬한 배열로 큐를 구성. 큐 계산 함수를 async로 설계하여 각 배너의 표시 조건을 비동기적으로 검사한 뒤 실제 표시할 배너 목록을 반환. 배너를 닫으면 현재 배너를 큐 앞에서 제거(dequeue)하고 다음 배너를 자동 표시. Enterprise 환경에서는 플랜 조건 검사 시점에 큐 진입 자체를 차단.
- **Result**: 배너 타입 추가 시 큐 배열에 항목 하나만 추가하면 되는 확장 가능한 구조, Enterprise / 일반 플랜 분기 일원화

### groupId 스코프 키 + 만료 기반 localStorage로 배너 닫힘 상태 격리

- **Problem**: 그룹 ID 없이 배너 타입만으로 localStorage 키를 구성하면, A 그룹에서 닫은 배너가 B 그룹에서도 닫힌 상태로 표시됐다(사용자가 여러 그룹에 속할 수 있는 구조). 또한 localStorage 값의 `value` 키가 없는 엣지 케이스를 처리하지 않아 배포 직후 핫픽스가 발생한 이력이 있었다.
- **Solve**: localStorage 키에 그룹 ID를 포함해 그룹별로 독립된 키로 저장. 만료 체크 시 저장된 데이터의 필수 필드 존재 여부를 먼저 확인하는 방어 코드 추가. 만료 체크 로직은 별도 유틸로 추출.
- **Result**: 그룹별 독립적인 배너 닫힘 상태 유지, localStorage 파싱 관련 엣지 케이스 방어

### 만료 시간 포함 localStorage 커스텀 래퍼로 클라이언트 상태 안전하게 관리

- **Problem**: 배너의 "오늘 하루 닫기" 기능은 정확히 하루 뒤 만료되어야 한다. 브라우저 기본 localStorage는 만료 기능을 제공하지 않아 별도 구현이 필요했다. 만료된 항목이 자동으로 제거되지 않으면 오래된 상태가 계속 남아 배너가 영원히 표시되지 않는 문제가 생긴다.
- **Solve**: 커스텀 localStorage 래퍼를 구현해 값과 만료 시각을 함께 저장. 읽기 시 만료 여부를 자동 체크하고, 만료된 항목은 즉시 삭제 후 기본값 반환. 배너 닫힘 상태는 1일 만료로 설정.
- **Result**: 브라우저 기본 localStorage에 만료 기능 추상화, 만료된 배너 닫힘 상태가 자동 초기화되어 다음 날 배너 재표시 보장

### next/dynamic 지연 로딩으로 배너 컴포넌트 초기 번들 제외

- **Problem**: 배너 컴포넌트는 조건을 만족할 때만 표시되는 선택적 UI임에도, 정적 import로 구성하면 초기 번들에 항상 포함된다.
- **Solve**: 각 배너 컴포넌트를 `next/dynamic`으로 동적 임포트하여 실제 렌더링 시점에만 로드되도록 처리.
- **Result**: 배너 컴포넌트가 초기 번들에서 제외되어 불필요한 번들 크기 증가 방지

## 회고 / 아쉬웠던 점

배포 직후 핫픽스는 localStorage 저장 데이터의 필수 필드 누락을 처리하지 않아 발생했다. 클라이언트 스토리지는 "데이터가 없을 수도 있고, 형식이 틀릴 수도 있다"는 전제 하에 항상 방어적으로 파싱해야 한다는 것을 몸소 배운 경험이었다. 이후로는 localStorage 접근 코드에 반드시 타입 체크와 존재 여부 확인을 먼저 추가하는 습관이 생겼다.
