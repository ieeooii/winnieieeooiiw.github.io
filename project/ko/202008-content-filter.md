## 소개

3D 의류 콘텐츠 목록 페이지에서 콘텐츠 타입·워크플로우·카테고리·검색 영역·정렬 등 다양한 필터를 조합하여 원하는 콘텐츠를 탐색하는 필터 시스템이다. **URL 쿼리 파라미터를 단일 진실 공급원(SSoT)으로 사용**하여 필터 상태를 URL에 직렬화하고, 페이지를 공유하면 동일한 필터 상태가 재현되도록 설계했다. 상태는 URL / LocalStorage / Cookie 세 계층에 목적에 맞게 분산 저장되며, MobX 스토어가 이를 통합 관리한다. 초기 구현 이후 카테고리 AND/OR 논리 연산자, 컬러웨이 뷰 모드, 워크플로우 V3 API 마이그레이션 등을 단계적으로 확장했다.

## 주요 구현

### URL 쿼리 파라미터 SSoT로 필터 상태 직렬화 및 공유 복원

- **Problem**: 필터는 콘텐츠 타입, 워크플로우(다중 선택), 카테고리, 검색 영역, 키워드, 정렬 방식, 정렬 방향 등 7가지 이상의 독립적인 상태를 가진다. 이를 컴포넌트 로컬 state로 관리하면 페이지 새로고침 시 초기화되고, URL 공유가 불가능하다. 반대로 모든 상태를 MobX 스토어에만 두면 URL이 상태와 분리되어 브라우저 뒤로가기·앞으로가기 동작과 어긋난다.
- **Solve**: URL 쿼리 파라미터를 타입 안전하게 파싱하여 스토어 초기값으로 설정. 필터 변경 시 shallow routing으로 URL만 업데이트하여 페이지 전체를 remount하지 않도록 처리. 워크플로우 ID 배열처럼 복수 값은 쉼표 구분 문자열로 직렬화·역직렬화. 누락된 파라미터는 LocalStorage 값 또는 기본값으로 폴백.
- **Result**: URL 공유 시 동일 필터 상태 재현, 브라우저 히스토리 기반 필터 탐색, shallow routing으로 불필요한 페이지 remount 방지

### 필터 성격별 URL / LocalStorage / Cookie 저장 계층 분리

- **Problem**: 필터 상태마다 지속성 요구사항이 달랐다. 카테고리·워크플로우·키워드는 세션 단위 상태라 URL에 두면 충분하지만, 정렬 방식과 정렬 방향은 사용자가 서비스 전체에서 선호하는 값이라 세션을 넘어 기억해야 했다. 뷰 모드(콘텐츠 단위 / 컬러웨이 단위)는 사용자별 UI 설정이라 더 장기적으로 유지되어야 했다.
- **Solve**: 필터 성격에 따라 저장 계층을 분리:
  - **URL 쿼리 파라미터**: 검색 조건(카테고리, 워크플로우, 키워드 등) — 공유 가능, 히스토리 추적 가능
  - **LocalStorage**: 정렬 방식·방향 선호 — 탭을 닫아도 유지, 같은 브라우저 내 모든 세션 공유
  - **Cookie**: 뷰 모드(콘텐츠 / 컬러웨이), 뷰어 모드(2D / 3D) — 장기 보존, 사실상 영구 유지
- **Result**: 각 필터 상태가 적합한 저장 계층에 위치하여, 페이지 이동·새로고침·세션 재시작 시에도 사용자 경험 일관성 유지

### 카테고리 AND/OR 연산자 토글로 복합 필터링 지원 (2022.03)

- **Problem**: 패션 MD가 여러 카테고리를 선택할 때 "선택한 카테고리를 모두 포함하는 콘텐츠"(AND)와 "선택한 카테고리 중 하나라도 포함하는 콘텐츠"(OR) 두 가지 탐색 방식이 모두 필요했다. 서버 API도 이 두 로직을 구분하여 처리해야 했고, 사용자가 현재 어떤 모드인지 직관적으로 파악할 수 있어야 했다.
- **Solve**: 카테고리 연산자 enum(AND / OR)을 정의하고, 카테고리 피커 상단에 토글 UI로 연산자 전환 구현. 선택된 연산자는 URL 쿼리에 포함되어 공유 가능. API 호출 시 연산자 파라미터로 전달하여 서버 레벨에서 AND / OR 집합 연산 처리.
- **Result**: 사용자가 AND / OR 모드를 직접 전환하며 복합 카테고리 필터링 가능, URL 공유 시 연산자 상태도 함께 재현

### 정렬 컨텍스트 기반 방향 자동 전환과 비호환 값 폴백 처리

- **Problem**: 정렬 옵션마다 자연스러운 기본 방향이 다르다. 최근 수정순은 내림차순이 자연스럽고, 이름순은 오름차순이 자연스럽다. 키워드 검색 중에는 관련도(Relevance) 정렬이 가장 유용하지만, 키워드가 없을 때는 관련도 정렬이 의미 없다. 또한 특정 정렬 옵션은 일부 페이지 컨텍스트에서 지원되지 않아 비호환 값이 LocalStorage에 남아있으면 에러가 발생했다.
- **Solve**: 정렬 변경 시 옵션별 자연스러운 방향을 자동 적용. 키워드 입력 시 관련도 정렬로 자동 전환, 키워드 제거 시 최근 수정순으로 복원. LocalStorage에서 불러온 정렬 값이 현재 컨텍스트에서 지원되지 않는 경우 기본값으로 reset하는 유효성 검사 추가.
- **Result**: 사용자가 정렬 방향을 매번 수동으로 조정하지 않아도 되는 UX, LocalStorage 비호환 값으로 인한 런타임 에러 방지

### 삭제된 워크플로우 필터 목록 노출 이슈 해결

- **Problem**: 워크플로우 설정에서 삭제된 상태도 필터 목록에 계속 표시되는 버그가 발생했다. 삭제된 워크플로우를 선택하면 해당 콘텐츠가 없음에도 빈 결과가 반환되어 사용자가 원인을 파악하기 어려웠다.
- **Solve**: 워크플로우 목록을 렌더링하기 전 삭제 플래그를 기준으로 유효 항목만 필터링하는 유틸 함수를 추출. 스토어에서 목록 세팅 시점에 적용하여 삭제된 항목이 UI에 노출되는 경우를 원천 차단.
- **Result**: 필터 목록에 유효한 워크플로우만 표시, 삭제된 항목 선택으로 인한 빈 결과 혼란 해소

### MobX Map 구조로 카테고리 O(1) 조회 최적화

- **Problem**: 선택된 카테고리 이름·계층 정보를 렌더링할 때마다 전체 카테고리 배열을 순회(O(n))하면, 선택 항목이 많아질수록 렌더링 비용이 선형으로 증가한다. 또한 선택된 카테고리를 계층 순서대로 표시해야 했지만 선택 순서가 계층 순서와 일치하지 않는 경우가 있었다.
- **Solve**: 카테고리 목록을 `Map<id, category>` 구조로 변환하여 저장, id 기반 O(1) 즉시 조회 가능하도록 처리. 선택된 카테고리를 계층 깊이 기준으로 정렬하여 상위 카테고리가 항상 먼저 표시되도록 구현.
- **Result**: 카테고리 렌더링 시 선형 탐색 제거, 선택 경로가 계층 순서대로 일관되게 표시

### TypeScript + Emotion 마이그레이션으로 디자인 시스템 연동 (2022.05)

- **Problem**: 초기 JavaScript + SCSS로 구현된 필터 컴포넌트는 디자인 시스템 토큰 적용이 불가능하고, 공통 드롭다운 컴포넌트 재사용도 어려웠다. 마이그레이션 전까지 필터 컴포넌트 간 암묵적 의존성이 있어 수정 범위를 예측하기 어려웠다.
- **Solve**: TypeScript + Emotion.js 기반으로 전면 마이그레이션. 디자인 시스템의 공통 드롭다운 컴포넌트로 교체하여 열림/닫힘 상태 관리와 외부 클릭 감지를 중앙화. 마이그레이션 과정에서 컴포넌트 간 암묵적 의존성을 발견하여 props 인터페이스를 명시적으로 재정의.
- **Result**: 디자인 시스템 토큰 적용 가능, 드롭다운 동작 일관성 확보, 컴포넌트 간 의존성 명시화

## 회고 / 아쉬웠던 점

필터 시스템 설계에서 가장 핵심적인 결정은 **"URL을 단일 진실 공급원으로 삼는 것"**이었다. URL에 필터 상태를 두면 공유·히스토리 추적·새로고침 복원이 모두 자연스럽게 해결되지만, 상태 변경마다 URL을 업데이트하고 URL 변경을 감지하여 상태를 복원하는 직렬화·역직렬화 레이어가 필요하다. 이 복잡도를 감수할 만한 UX 이점이 있다고 판단했고, shallow routing으로 성능 문제를 해결했다. 또한 정렬·뷰 모드처럼 "사용자 개인 선호"에 해당하는 상태는 URL보다 LocalStorage/Cookie가 적합하다는 것을 실무에서 직접 구분 기준을 세우며 배웠다.
