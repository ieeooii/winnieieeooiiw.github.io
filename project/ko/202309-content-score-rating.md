# 콘텐츠 완성도 점수 & 평점 기능 개발

| 항목 | 내용 |
|------|------|
| 회사 | CLO Virtual Fashion |
| 카테고리 | SaaS |
| 서비스 | CLO-SET |
| 기술 스택 | Next.js, TypeScript, React Query, Emotion |
| 개발 기간 | 2023.09 ~ 2023.10 |
| 서비스 링크 | style.clo-set.com |

## 소개

3D 의류 콘텐츠의 품질을 별점과 점수로 평가하는 Score/Rating 기능이다. 패션 MD가 콘텐츠 완성도를 정량적으로 기록하고, 팀 내 리뷰 워크플로우에서 품질 기준을 공유할 수 있도록 지원한다. **편집 권한(canEdit) 기반 접근 제어**가 핵심 설계 요소였다 — 권한이 있는 사용자에게는 인터랙티브한 편집 UI를, 없는 사용자에게는 읽기 전용 뷰를 제공해야 했다. React Query 기반 서버 상태 동기화와 MutationObserver 패턴을 통해 낙관적 UI 업데이트(Optimistic Update)를 구현했다.

## 주요 구현

### 권한 기반 이중 렌더링 모드 (canEdit)

- **Problem**: Rating UI는 권한 여부에 따라 완전히 다른 인터랙션을 제공해야 했다. 단순히 버튼을 `disabled` 처리하는 것은 좋지 않은 UX다 — 권한 없는 사용자에게 클릭할 수 없는 요소가 보이면 혼란을 준다. 동시에 읽기 전용과 편집 가능 모드가 동일한 컴포넌트 내부에 혼재하면 조건 분기가 복잡해지고, 향후 두 모드 중 하나만 변경해야 할 때 사이드 이펙트가 발생한다.
- **Solve**: 별점 컴포넌트를 편집 권한 prop 기반으로 두 가지 렌더링 경로로 분기. 편집 가능 시에는 hover/click 이벤트가 바인딩된 인터랙티브 UI를 렌더링하고, 읽기 전용 시에는 동일한 시각적 디자인이지만 이벤트 핸들러가 없는 순수 표시용 컴포넌트를 렌더링. CSS `pointer-events: none`으로 차단하여 스크린리더와 키보드 사용자 모두 편집 불가 상태를 명확히 인식하도록 처리.
- **Result**: 권한별 명확히 구분된 UX 제공, 컴포넌트 내부 조건 분기 최소화

### React Query 기반 서버 상태 동기화

- **Problem**: 별점 변경은 사용자에게 즉각적인 피드백이 필요하지만, API 호출에는 네트워크 지연이 존재한다. 별점을 클릭할 때마다 API 응답을 기다리면 UI가 버벅이는 것처럼 느껴지고, 반대로 클라이언트 상태만 업데이트하면 서버 저장 실패 시 UI와 실제 데이터가 불일치하게 된다.
- **Solve**: 점수 조회 쿼리 훅으로 서버에서 현재 점수 조회, 점수 업데이트 뮤테이션 훅으로 업데이트 처리. Mutation의 `onMutate` 콜백에서 낙관적 업데이트(Optimistic Update)를 적용하여 API 호출 전에 UI를 즉시 반영. `onError` 콜백에서 이전 상태로 롤백(rollback)하고 사용자에게 오류 토스트 표시. `onSettled`에서 `invalidateQueries`로 최신 서버 상태를 재조회하여 최종 동기화.
- **Result**: 네트워크 지연 없이 즉각적인 별점 변경 피드백, API 실패 시 자동 롤백으로 데이터 정합성 보장

### Score 상세 모달 구현

- 점수 구성 요소(항목별 세부 점수, 총점)를 시각화하는 상세 모달 개발
- 요약 점수 표시 컴포넌트를 클릭하면 항목별 상세 점수 모달로 drill-down하는 계층 구조 설계
- 점수 항목별 가중치와 계산 방식을 사용자가 이해할 수 있도록 breakdown 형태로 표현

## 회고 / 아쉬웠던 점

Optimistic Update는 UX를 크게 향상시키지만, 롤백 로직을 꼼꼼하게 처리하지 않으면 실패 케이스에서 데이터 불일치가 발생한다. 이 작업에서 React Query의 `onMutate → onError → onSettled` 사이클을 처음으로 완전하게 구현해보면서, **낙관적 업데이트는 "성공 경로"와 "실패 경로"를 함께 설계해야만 완성된다**는 것을 배웠다. 또한 권한 기반 UI 분기는 "조건 처리"가 아니라 "컴포넌트 모드 전환"으로 접근하는 것이 유지보수 측면에서 훨씬 낫다는 것을 확인했다.
