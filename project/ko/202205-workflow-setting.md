## 소개

패션 브랜드 관리자가 워크플로우(Draft / In Review / Approved 등 작업 상태)를 직접 등록·수정·삭제하고 순서를 정할 수 있는 Admin 설정 페이지다. 드래그 앤 드롭 가능한 공통 Setting 컴포넌트 레이어를 먼저 설계하고, 각 도메인이 그 위에 올라타는 구조를 잡았다.

![워크플로우 설정](/images/projects/202008-content-filter-workflow.png)

## 주요 구현

### 드래그 앤 드롭 공통 Setting 컴포넌트 설계로 도메인별 재사용 구조 확립

- **Problem**: 정렬 가능한 리스트 UI를 각 설정 도메인마다 따로 만들면 코드 중복이 발생하고, 이후 동일한 패턴의 설정 항목이 추가될 때마다 반복 구현이 필요했다. 당시 `react-beautiful-dnd`가 메인스트림이었지만 React Strict Mode와의 호환성 이슈가 있었고, 디자인 시스템 드래그 핸들 아이콘과의 통합도 필요했다.
- **Solve**: 전체 리스트 컨테이너와 개별 항목을 독립 컴포넌트로 분리 설계. 각 도메인 컴포넌트는 이 레이어에 데이터만 주입하는 방식으로 구현. 드래그 핸들 아이콘을 디자인 시스템에 추가하여 일관된 인터랙션 제공.
- **Result**: Workflow 설정에서 검증된 공통 컴포넌트가 이후 추가되는 설정 도메인에서 즉시 재사용 가능한 구조 확립

### SSR→CSR 전환과 Shallow Route로 탭 전환 속도 2000ms→250ms 개선

- **Problem**: 설정 페이지 탭 전환 시 매번 SSR 요청이 발생하여 탭 간 이동에 2000ms 이상 소요됐다.
- **Solve**: 데이터 GET API를 SSR Request에서 CSR로 전환하고 데이터 캐싱 적용. 탭(URL Path) 전환에 Shallow Route를 적용하여 페이지 전체를 remount하지 않도록 처리. 탭별 컴포넌트에 dynamic import를 적용하여 초기 다운로드 번들 사이즈를 대폭 축소. Intersection Observer API로 뷰포트 진입 시 lazy load 구현.
- **Result**: 탭 전환 속도 2000ms → 250ms 개선 / 첫 다운로드 사이즈 1GB 축소 및 속도 200% 개선

### 빈 값·취소·날짜 포맷 엣지 케이스 방어로 잘못된 데이터 서버 전송 차단

- **Problem**: ① 빈 값으로 추가 버튼을 클릭했을 때 유효성 검사가 누락되어 빈 항목이 서버에 저장됐다. ② 편집 후 취소를 눌렀을 때 입력 컴포넌트의 상태가 초기화되지 않아 취소 후 다시 열면 이전 내용이 남아있었다. ③ 날짜 입력에서 잘못된 포맷이 서버로 전달됐다.
- **Solve**: ① 빈 값 유효성 검사 추가. ② 취소 버튼 이벤트에 입력 상태 초기화 로직 추가. ③ 날짜 유효성 검사 구현 및 입력 필드에 적용.
- **Result**: 잘못된 데이터 서버 전송 차단, 편집 취소 후 UI 상태 초기화 정상 동작

## 회고 / 아쉬웠던 점

관리자 설정 페이지는 간단하다는 선입견이 있었는데, 실제로는 입력 유효성 검사·상태 초기화·순서 변경 API 동기화 등 예외 케이스가 생각보다 많았다. 공통 컴포넌트 설계를 먼저 한 덕분에 이후 설정 도메인이 추가됐을 때 레이아웃 코드를 거의 재사용할 수 있었다. 반복되는 패턴이 보이면 세 번째 사용처가 생기기 전에 공통화하는 것이 맞다는 것을 이 작업에서 배웠다.
