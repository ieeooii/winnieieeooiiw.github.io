## 소개

콘텐츠 공유 URL을 QR 코드로 생성하고 PNG 파일로 다운로드하는 기능이다. 패션쇼·전시 현장에서 관람객이 QR 코드를 스캔해 3D 의류 콘텐츠로 즉시 접근할 수 있는 오프라인-온라인 연결 시나리오를 지원한다. 단순한 QR 생성 라이브러리 호출을 넘어, **Canvas API 기반 커스텀 렌더링**과 **Share 컴포넌트 계층 설계**가 핵심이었다. 이후 Embed Viewer에서도 동일 컴포넌트를 재사용하여 코드 중복 없이 기능이 확장됐다.

## 주요 구현

### Canvas API 기반 QR 코드 렌더링 및 PNG 다운로드

- **Problem**: 브라우저에서 QR 이미지를 `.png` 파일로 다운로드하려면 단순히 `<img>` 태그로 렌더링하는 것만으로는 부족하다. `<img>` 태그의 이미지는 직접 파일로 추출하기 위한 별도 처리가 필요하며, 특히 QR 코드 위에 CLOSET 로고를 합성하는 요구사항이 있어 DOM 기반 렌더링으로는 한계가 있었다. 또한 다운로드 파일명을 콘텐츠 이름으로 지정해야 하는데, anchor 태그의 `download` 속성이 cross-origin 환경에서 동작하지 않는 문제도 있었다.
- **Solve**: QR 코드를 `<canvas>` 엘리먼트에 직접 렌더링하고, 로고 이미지를 `drawImage()`로 캔버스 위에 합성. 완성된 캔버스를 `canvas.toDataURL('image/png')`로 base64 Data URL로 추출한 뒤, programmatic anchor click(`a.href = dataURL`, `a.download = fileName`)으로 다운로드 트리거. cross-origin 문제 없이 클라이언트에서 완전히 처리.
- **Result**: 로고 합성 QR PNG 파일 다운로드 안정적으로 동작, 서버 요청 없이 클라이언트에서 완결되는 구조로 응답속도 최적화

### Share 컴포넌트 아키텍처 설계 및 Embed Viewer 재사용

- **Problem**: Share 기능은 URL 복사, SNS 공유, QR 코드 등 여러 공유 방식을 지원해야 했는데, 각 방식을 독립된 컴포넌트로 분리하지 않으면 단일 Share 컴포넌트가 비대해지는 문제가 발생한다. 또한 Embed Viewer에서도 동일한 QR 공유 기능이 필요했는데, 컴포넌트 구조가 특정 페이지에 강하게 결합되어 있으면 재사용이 불가능하다.
- **Solve**: `ShareQRCode.tsx`(QR 코드 생성·렌더링)와 `ShareQRCodeMiniModal.tsx`(QR 표시용 미니 모달)를 분리 설계. Share 관련 컴포넌트 전체를 `components/share/right/*` 폴더로 구조 정리하여 공유 방식별 컴포넌트가 독립 모듈로 관리되도록 응집도 향상. Embed Viewer에서는 `ShareQRCode.tsx`만 가져다 쓰는 방식으로 QR 기능 즉시 재사용.
- **Result**: Share 컴포넌트 구조 명확화, Embed Viewer에 코드 중복 없이 QR 기능 통합

## 회고 / 아쉬웠던 점

QR 코드 기능은 작아 보이지만, "파일 다운로드"라는 요구사항 하나가 Canvas API → Data URL → Anchor programmatic click이라는 연쇄적인 기술 선택으로 이어졌다. 브라우저 API를 직접 다루는 작업에서는 **"어떤 브라우저 제약이 있는가"를 먼저 파악하는 것**이 구현 방향을 결정한다는 것을 배웠다. 또한 컴포넌트를 처음부터 재사용 가능하게 분리해 두면, 나중에 "여기에도 필요한데?"라는 요청이 왔을 때 거의 비용 없이 대응할 수 있다는 것을 이 작업에서 확인했다.
