## 소개

3D 의류 콘텐츠의 품질을 별점과 점수로 평가하는 Score/Rating 기능이다. 패션 MD가 콘텐츠 완성도를 정량적으로 기록하고, 팀 내 리뷰 워크플로우에서 품질 기준을 공유할 수 있도록 지원한다. **편집 권한 기반 접근 제어**가 핵심 설계 요소였다 — 권한이 있는 사용자에게는 인터랙티브한 편집 UI를, 없는 사용자에게는 읽기 전용 뷰를 제공해야 했다. React Query 기반 서버 상태 동기화와 낙관적 UI 업데이트(Optimistic Update)를 구현했다.

## 주요 구현

### 권한 기반 이중 렌더링 모드

- **Problem**: Rating UI는 권한 여부에 따라 완전히 다른 인터랙션을 제공해야 했다. 단순히 버튼을 `disabled` 처리하는 것은 좋지 않은 UX다 — 권한 없는 사용자에게 클릭할 수 없는 요소가 보이면 혼란을 준다. 동시에 읽기 전용과 편집 가능 모드가 동일한 컴포넌트 내부에 혼재하면 조건 분기가 복잡해지고, 향후 두 모드 중 하나만 변경해야 할 때 사이드 이펙트가 발생한다.
- **Solve**: 별점 컴포넌트를 편집 권한 prop 기반으로 두 가지 렌더링 경로로 분기. 편집 가능 시에는 hover/click 이벤트가 바인딩된 인터랙티브 UI를 렌더링하고, 읽기 전용 시에는 동일한 시각적 디자인이지만 이벤트 핸들러가 없는 순수 표시용 컴포넌트를 렌더링. `pointer-events: none`으로 차단하여 스크린리더와 키보드 접근성도 함께 처리. 편집 버튼은 데이터 로딩 완료(`isFetched`) 후에만 활성화하여 미로딩 상태에서 모달이 열리는 엣지 케이스를 차단.
- **Result**: 권한별 명확히 구분된 UX 제공, 컴포넌트 내부 조건 분기 최소화

### Optimistic Update — onMutate / onError / onSettled 사이클

- **Problem**: 별점 변경은 사용자에게 즉각적인 피드백이 필요하지만, API 호출에는 네트워크 지연이 존재한다. 별점을 클릭할 때마다 API 응답을 기다리면 UI가 버벅이는 것처럼 느껴지고, 반대로 클라이언트 상태만 업데이트하면 서버 저장 실패 시 UI와 실제 데이터가 불일치하게 된다.
- **Solve**: Mutation의 `onMutate`에서 쿼리 캐시를 즉시 교체하여 API 응답 전에 UI를 반영. `onError`에서 저장해둔 이전 캐시값으로 롤백하고 오류 토스트 표시. `onSettled`에서 `invalidateQueries`로 서버 최신 상태를 재조회하여 최종 동기화. 모달은 독립적인 로컬 draft 상태를 유지하므로 취소 시 캐시에 영향 없이 원래 값으로 복원.
- **Result**: 네트워크 지연 없이 즉각적인 별점 변경 피드백, API 실패 시 자동 롤백으로 데이터 정합성 보장

### 평점 UX 엣지 케이스 처리

- **Problem**: 10점 척도 평점에서 이미 선택한 값을 다시 선택했을 때 "선택 해제"가 가능해야 했다. 별도의 초기화 버튼을 두면 UI가 복잡해지고, 단순 재클릭으로 해제되면 직관적이지만 구현 시 1점 재클릭과 일반 클릭을 구분해야 한다. 또한 hover 미리보기와 최종 확정값을 분리하여 관리해야 했다.
- **Solve**: 평점 컴포넌트 내부에 hover 미리보기용 상태와 최종 확정값 상태를 분리. `onMouseOver`로 미리보기를 표시하고 `onMouseLeave`로 확정값으로 복원. 1점을 이미 선택한 상태에서 재클릭하면 0(미선택)으로 토글하는 조건을 별도 처리. Portal 렌더링은 `useEffect`에서 DOM을 조회하여 SSR 안전하게 처리하고, 대상 컨테이너가 없을 경우 `document.body`로 fallback.
- **Result**: 별도 삭제 버튼 없이 1점 재클릭으로 자연스러운 선택 해제, hover 미리보기와 확정값 상태 분리로 인터랙션 안정화

## 회고 / 아쉬웠던 점

Optimistic Update는 UX를 크게 향상시키지만, 롤백 로직을 꼼꼼하게 처리하지 않으면 실패 케이스에서 데이터 불일치가 발생한다. 이 작업에서 React Query의 `onMutate → onError → onSettled` 사이클을 처음으로 완전하게 구현해보면서, **낙관적 업데이트는 "성공 경로"와 "실패 경로"를 함께 설계해야만 완성된다**는 것을 배웠다. 또한 권한 기반 UI 분기는 "조건 처리"가 아니라 "컴포넌트 모드 전환"으로 접근하는 것이 유지보수 측면에서 훨씬 낫다는 것을 확인했다.
