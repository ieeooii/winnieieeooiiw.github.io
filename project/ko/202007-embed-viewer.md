## 소개

3D 의류 파일(.zpac, .zprj 등), 렌더링 이미지, 터테이블 등 다양한 포맷의 의상 콘텐츠를 외부 웹사이트에 iframe으로 임베드할 수 있는 Embed Viewer 기능이다. 단순 iframe 삽입을 넘어, 기업 고객이 도메인 화이트리스트 기반의 접근 제어 정책을 직접 관리하고, 뷰어 UI·배경색·로고·자동회전 등 세부 옵션을 커스터마이징할 수 있도록 설계했다. 뷰어 타입(3D / 렌더링 / 터테이블 / 2D 이미지)에 따라 렌더링 파이프라인과 데이터 페칭 전략이 달라지는 복잡한 구조를 MobX 기반 단일 스토어로 통합·관리했다.

## 주요 구현

### 멀티 뷰어 타입 아키텍처 설계

- 하나의 Embed URL이 3D, 렌더링, 터테이블, 2D 이미지, 패턴 등 5가지 뷰 타입을 지원하도록 라우팅 및 컴포넌트 분기 설계
- 파일 타입(CLO3D / 터테이블 / 외부 3D / 기타)과 뷰 타입을 교차하여 렌더링 전략을 결정하는 뷰어 컨테이너 설계, 내부에서 3D 뷰어와 이미지 뷰어 중 하나를 조건부 마운트
- 외부 3D 포맷(fbx, obj, glb, dae 등)과 CLO 네이티브 포맷을 모두 처리하는 파일 타입 체계 수립

### MobX 기반 EmbedStore 설계

- **Problem**: 뷰어 상태(컬러웨이 인덱스, 뷰 타입, 로딩 진행률, 배경색 등)와 옵션(UI 표시 여부, 로고, 자동회전, 렌더 품질 등)이 컴포넌트 간 prop-drilling으로 전달되어 깊이가 4단계 이상으로 내려가고, 뷰어 타입 전환 시 상태 초기화 시점을 제어하기 어려웠다.
- **Solve**: 뷰어 코어 상태 / 표시 옵션 / 비동기 프로세스 상태를 세 클래스로 계층 분리. URL 쿼리 파라미터에서 옵션을 파싱하여 초기 상태를 세팅하고, 이후 사용자 상호작용은 스토어를 통해서만 변경되는 단방향 흐름 구축.
- **Result**: 컴포넌트는 스토어 구독만으로 상태 수신, 깊은 prop-drilling 제거. 뷰 타입 전환 시 스토어 메서드 하나로 일관된 초기화 가능.

### 도메인 화이트리스트 기반 Private Embed Viewer (PEV)

- **Problem**: 엔터프라이즈 고객이 자사 도메인에서만 임베드가 작동하도록 제한하고 싶지만, iframe 특성상 서버가 요청 출처를 검증하기 어렵고, 어드민이 도메인을 직접 관리할 UI도 없었다.
- **Solve**: API 요청 시 커스텀 헤더로 임베드 출처 도메인을 서버에 전달. 백엔드와 함께 공개 / 비활성화 / 허용 사이트 전용 세 가지 접근 정책 체계를 설계. 어드민 콘솔에 허용 도메인 CRUD UI 구현.
- **Result**: 기업 고객이 허용 도메인을 직접 관리하고, 허용되지 않은 도메인에서의 임베드 요청은 서버에서 차단되는 완전한 접근 제어 플로우 구현.

### Embed 옵션 쿼리 파라미터 직렬화 / 역직렬화

- Embed Modal에서 사용자가 설정한 배경색, 로고 색상, UI 표시 여부, 자동회전, 텍스처 품질, 뎁스 필링, 스카이박스 등 8가지 옵션을 URL 쿼리 스트링으로 직렬화하여 iframe src에 반영
- 쿼리 파라미터를 파싱하여 스토어 초기값으로 복원, 임베드 URL만으로 완전한 뷰어 재현 가능
- Embed Modal의 실시간 미리보기에서 옵션 변경 즉시 URL이 갱신되도록 구현

### 사용량 추적 및 플랜 제한 처리

- **Problem**: 임베드 뷰어 조회 수를 플랜별로 제한해야 하지만, iframe 내에서 발생하는 API 요청이 중복 카운트될 수 있었다.
- **Solve**: 최초 데이터 페치 시에만 카운트가 집계되도록 플래그 제어 로직 구현. 사용량 초과 시 서버가 반환하는 에러 응답을 별도 케이스로 매핑하여 제한 안내 화면으로 분기.
- **Result**: 정확한 사용량 집계와 함께 사용자에게 명확한 제한 안내 제공.

### 컬러웨이 전환 및 텍스처 품질 제어

- 3D 뷰어에서 컬러웨이 변경 시 뷰어 엔진 API를 호출하여 텍스처를 교체하고, 렌더링 뷰 타입에서는 컬러웨이별 이미지 시퀀스를 새로 페치하는 분기 처리
- 텍스처 품질을 고화질 / 최적화 두 단계로 제어하여 임베드 환경(저사양 기기, 저대역폭)에서도 안정적인 재생 보장
- 뎁스 필링(Depth Peeling) 기법 적용 옵션을 제공하여 반투명 소재(시스루, 레이스 등)를 정확하게 렌더링

## 회고 / 아쉬웠던 점

"하나의 URL이 다양한 상태를 완전히 재현해야 한다"는 요구사항이 설계 전반에 영향을 줬다. 쿼리 파라미터를 단순히 초기값으로 사용하는 것과, 스토어 상태와 URL을 항상 동기화된 단일 진실 공급원(SSoT)으로 유지하는 것은 구현 복잡도가 크게 다르다. 초기에는 두 방향을 혼용했지만, 결국 쿼리 파라미터는 초기화 시에만 읽고 이후엔 스토어만 믿는 방향으로 정리하면서 구조가 단순해졌다. 도메인 화이트리스트 검증처럼 "신뢰 경계"가 클라이언트-서버 사이에 명확히 존재하는 기능은, 클라이언트에서 아무리 잘 막아도 서버 검증이 전제되어야 한다는 점을 다시 한번 확인한 계기가 됐다.
